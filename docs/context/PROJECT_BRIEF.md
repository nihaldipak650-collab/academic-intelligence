# Project Brief

## 项目目标

Academic Intelligence 是面向本科生的导师公开信息理解工具。它在公开证据边界内整理导师研究方向、方法门槛、可能的本科参与路径和联系前仍需核验的信息，帮助用户形成问题与判断依据；它不是导师排名、推荐或人格评价系统。

## 目标用户

- 主要用户：正在了解科研、选择方向或准备联系导师的本科生，尤其是低年级学生。
- 核心需要：读懂研究方向与技术语言，区分可靠证据和未知信息，并知道下一步该核验什么。

## 1.0 范围

- 只读静态前端；不含账号、数据库、在线编辑、AI 问答、导师排名或自动推荐。
- 展示公开的 Academic Evidence 及其边界、来源和置信度。
- Experience Evidence 是独立、可选、默认不公开的材料；任何公开使用需单独隐私与授权审查。
- 当前前端数据仍通过 `web/advisors.json` 与 `web/reports/*.md` 同步到 `frontend/public/`，不是目标中的规范化 JSON 生产链路。

## 三条工作主线

1. **导师证据生产**：身份确认、论文检索与去重、Evidence Manifest、语义审计、结构化资料与确定性报告。
2. **产品与前端**：把已批准的公开字段映射为可读、可搜索、可复核的静态体验。
3. **研究与治理**：本科生需求研究、隐私授权、公开边界、质量门禁、发布与回滚。

## 分工

- **用户**：最终产品负责人；批准范围、隐私边界、导师内容、发布、部署和批次推进。
- **Codex**：以 Git 和文件为依据执行仓库检查、实现、测试、审计和交接；不得代替用户批准发布或放宽证据边界。
- **Antigravity**：在已批准合同下收集公开资料、整理 Evidence、生成结构化 JSON 与确定性 Markdown，并做机械校验；不得决定隐私授权、接站或发布。当前合同位于本地分支 `feature/advisor-template-v1`，尚未确认合并或远程发布。
- **ChatGPT**：用于需求讨论、研究归纳和方案形成；其输出是分析或建议，只有经用户明确批准并由仓库证据确认后，才能成为项目决定或仓库事实。
